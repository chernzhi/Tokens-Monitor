# AI Token 监控 — 客户端使用说明

本文说明 **Windows 客户端**（`ai-monitor.exe`）的作用、安装方式、配置项与常见问题。面向本机使用者与需要分发给同事的运维同事。

---

## 一、程序是做什么的

本程序在本机启动一个 **HTTP/HTTPS 代理（MITM）**，把经过代理的 **AI 相关 HTTPS 流量**解密后：

- 尽量从响应里解析 **token 用量**（各厂商 JSON 里的 `usage` 等）；
- 将统计结果上报到公司配置的 **服务端**（`config.json` 里的 `server_url`），供大屏汇总与分摊。

**前提**：开发工具（VS Code、Cursor、CLI 等）发出的 AI 请求必须先 **经过本代理**，否则无法统计。当前推荐方式是：用 `ai-monitor.exe --launch <你的程序>` 只对子进程注入代理环境变量，而不是改系统代理。

常见入口已经支持预设：`vscode`、`cursor`、`powershell`、`cmd`，可直接用 `--launch-preset` 启动。若这些程序没加进 `PATH`，客户端还会自动尝试常见 Windows 安装目录。

**不能做什么**：无法保证「未走本代理的流量」被统计；无法替代各厂商官方计费账单；部分 **gRPC / 非 JSON** 场景仅能做体积类 **粗算**（若开启 `report_opaque_traffic`）。

---

## 二、工作原理（简版）

1. 本程序监听 `config.json` 中的 `port`（默认 `18090`），提供 **HTTP 代理**（`CONNECT` 隧道 + 对列入名单的域名做 HTTPS 解密）。
2. `config.json` 中列出一批默认 **AI 相关域名**（OpenAI、GitHub Copilot、Cursor、Anthropic、OpenRouter 等）；命中则 **MITM** 并尝试解析用量。
3. 未列入的域名一般 **只做透传**，不解密。
4. 需要本机安装本工具生成的 **根证书（CA）**，否则浏览器/IDE 会提示证书错误。

**重要**：本程序是 **HTTP 代理**，**不是 SOCKS5 服务**。在 Proxifier 等软件里请选 **HTTP/HTTPS 代理** 指向 `127.0.0.1:端口`，不要选 SOCKS5 指向同一端口。

---

## 三、环境要求

- Windows 10/11（当前客户端针对 Windows 构建）。
- 能访问公司部署的 **上报服务**（默认示例为 `https://otw.tech:59889`，以你方实际为准）。
- 若使用 **MITM**，需能安装证书到 **当前用户** 证书存储（首次双击 `ai-monitor.exe` 的安装向导会处理）。

---

## 四、第一次使用（推荐）

1. 解压 **`ai-monitor-分发版.zip`** 到本机任意目录。
2. 双击 **`ai-monitor.exe`**。
3. 第一次运行时会自动打开安装/登录向导，按提示完成配置、证书安装和后台启动。
4. 安装完成后一般不需要再点其它脚本；以后开机后程序会自动在后台运行。
5. 如果需要重新配置，直接再次双击 **`ai-monitor.exe`**，或在命令行运行 `ai-monitor.exe --setup`。

分发包里只保留两个辅助入口：

- **`卸载.bat`**：完整卸载证书、代理/PAC、环境变量、开机自启，并清理 `%APPDATA%/ai-monitor` 配置目录。
- **`修复网络.bat`**：异常退出后网络代理不正常时使用。

## 五、配置文件 `config.json`

安装向导会生成一个带 `//` 注释说明的 **`config.json`**。这个文件采用 JSONC 风格：`//` 开头的行是给人看的说明，ai-monitor 和 VS Code 扩展都会自动忽略。VS Code 扩展也会优先读取同一个 `%APPDATA%/ai-monitor/config.json`，不再需要单独维护 `identity.json`。

可参考同目录下的 **`config.example.json`**。常用字段说明：

| 字段 | 含义 |
| ------ | ------ |
| `server_url` | 上报服务根地址，例如 `https://otw.tech:59889` |
| `user_name` / `user_id` / `department` | 大屏展示用身份与部门 |
| `port` | 本机 MITM 监听端口（默认 `18090`）；被占用时程序可能自动顺延到下一可用端口 |
| `upstream_proxy` | 本地 MITM 外联时使用的上游代理，可填 `http://...`、`https://...` 或 `socks5://...`，用于串联公司代理 |
| `install_system_proxy` | 为 `true` 时，执行安装会写入 Windows 系统代理例外等；省略时默认 `false`，不改本机网络 |
| `install_ide_proxy` | 默认 `false`：不往 VS Code/Cursor 的 `settings.json` 写 `http.proxy`，避免与系统代理重复；扩展若完全不走系统代理再考虑改为 `true` 并重新安装 |
| `report_opaque_traffic` | 对难以解析正文的流量是否做体积类粗算上报（可按需关闭） |
| `mitm_cursor` | **默认 `false`（推荐）**：Cursor 桌面端钉证书，开启会让 Cursor 登录失败/网络断连；仅在确认本机 Cursor 已不再 pin 时才置 `true` |
| `report_proxy` | 上报服务器流量的代理策略：`auto`/空、`direct`、`upstream` 或具体代理地址 |
| `monitor_hosts` | 完整 **精确主机名 → 供应商标签** 监控表；可直接增删改 |
| `monitor_suffixes` | 完整 **域名后缀 / 前缀+后缀 → 供应商标签** 通配监控规则 |
| `auth_token` / `api_key` | 上报认证信息，属于敏感字段，不要公开分享 |

修改配置后：若改了端口、上游代理、安装模式或域名列表，请重新双击 **`ai-monitor.exe`** 或执行 `ai-monitor.exe --setup`，让 PAC/代理配置重新生成。

## 七、命令行参数（进阶）

在 `client` 目录下于 PowerShell/CMD 中执行，例如：

```text
ai-monitor.exe                    # 正常运行 MITM
ai-monitor.exe --setup            # 仅向导配置
ai-monitor.exe --install          # 默认仅安装 CA，不改系统代理
ai-monitor.exe --install-full     # 强制写系统代理（legacy 模式）
ai-monitor.exe --launch code.cmd  # 仅对子进程注入代理环境变量并启动目标应用
ai-monitor.exe --launch-preset vscode
ai-monitor.exe --launch-preset cursor
ai-monitor.exe --launch-preset powershell
ai-monitor.exe --list-launch-presets
ai-monitor.exe --install-cert-only
ai-monitor.exe --uninstall        # 卸载并清理安装配置
ai-monitor.exe --global-uninstall # 完整卸载（卸载.bat 使用此模式）
ai-monitor.exe -config 路径.json  # 指定配置文件
```

具体以程序 `--help` 输出为准。

## 八、与 Proxifier 共用时的要点

1. **`ai-monitor.exe` 必须「直连 / Direct」**，不要让它自己的出站再进本机代理，否则易 **环路**，导致 Copilot 无响应、上报失败。
2. 指向本机 MITM 时，类型选 **HTTP 代理**，地址 `127.0.0.1`，端口与 **`config.json` 的 `port` 及实际监听一致**。
3. 可勾选 **「通过系统代理连接」**，减少与 Windows 系统代理规则冲突。
4. 避免 **同一连接被代理两次**（系统代理 + Proxifier 重复指向）。

## 九、VS Code / GitHub Copilot / Cursor

- 安装好 **CA** 后，Copilot、Cursor 等走 MITM 的 HTTPS 才不会因证书失败。
- 默认推荐用 `--launch` 启动目标程序，让 Electron/CLI 只在当前进程内走 MITM；若确需整机导流，再考虑系统代理模式。
- 若你的同事不想记命令，可优先用 `--launch-preset vscode`、`--launch-preset cursor` 或 `--launch-preset powershell`；即使这些程序未加入 `PATH`，也会优先尝试常见安装目录。
- 客户端新版本已对 **HTTP/2**、**Copilot / Claude 与 OpenAI 不同请求体** 做区分（例如不会对 Anthropic 通道注入 OpenAI 专有字段），请尽量使用 **当前仓库编译的最新 `ai-monitor.exe`**。

## 十、自检命令

在监控已启动时（端口以你配置为准）：

```powershell
Invoke-RestMethod "http://127.0.0.1:18090/status"
```

应返回 `status: running`，并带有当前 **`version`**、用户信息等。

## 十一、常见问题

| 现象 | 可能原因 | 处理 |
| ------ | ---------- | ------ |
| 大屏无数据 | 本机未走代理或监控未开 | 确认窗口在跑、系统/IDE/Proxifier 指向正确端口 |
| 证书错误 | 未安装 CA | 双击 `ai-monitor.exe` 重新进入向导，或按界面提示手动信任根证书 |
| Copilot 不回复 | Proxifier 环路、协议选错、旧版本 exe | `ai-monitor` 直连、用 HTTP 代理非 SOCKS5、换新版客户端 |
| `/status` 版本很旧 | 实际运行的是别的目录下的旧 exe | 结束旧进程后，在 **当前分发目录** 启动新 `ai-monitor.exe` |
| Cursor 频繁掉线 / 登录失败 | 旧版本 `mitm_cursor=true` MITM 了钉证书的 Cursor | 升级到当前版本（默认 `mitm_cursor=false`）；若你曾手动改成 true，请改回 false 或删掉该字段 |

## 十一·B、双击 `ai-monitor.exe` 后什么会变？什么不会变？

**v3.1.2 起默认是「会话 PAC 模式」**：

| 项 | 行为 |
| ------ | ------ |
| AI 域名（OpenAI / Anthropic / Cursor / Copilot / Codex 等白名单内）| 临时写一份 PAC，路由到本机 MITM 做监控；**关闭 ai-monitor 程序时自动还原** |
| 非 AI 域名（公司内网 / GitHub / VS Code 市场 / 浏览器普通上网） | 通过 PAC 直连，不经过 ai-monitor，**不影响**正常网络 |
| `HTTP_PROXY` / `HTTPS_PROXY` 用户级环境变量 | **不写**，不污染 npm/pip/curl |
| Cursor 桌面端（钉证书） | MITM 透传（`mitm_cursor=false` 默认），**不会断连** |
| 已经在跑的 IDE（Electron 进程） | 启动时 ai-monitor 检测到会询问 `Y/n`，选 Y 自动重启让监控生效 |

如果你想要老式「观察模式」（端口监听但不动系统），把 `config.json` 里 `auto_install_session_pac` 改为 `false`。

如果你升级前曾经历过「一打开 ai-monitor 编程工具网络就坏」，多半是旧版本留下了下面这些**残留**之一：

1. 注册表里残留 `AutoConfigURL = file:///%APPDATA%/ai-monitor/proxy.pac` 但 PAC 文件已删；
2. `HKCU\Environment` 里残留 `HTTP_PROXY=http://127.0.0.1:18090`，指向已 dead 的端口；
3. `%APPDATA%\ai-monitor\install_state.json` 里 `session_only=true` 但实际系统已干净（"幽灵状态"）。

新版本启动时会**自动**清理上述残留；如果担心还在，**一键修复**步骤：

```cmd
:: 1) 在分发目录里双击「修复网络.bat」
::    它会按顺序调用:
::      ai-monitor.exe --cleanup-network   ← 完整清理 PAC/代理/环境变量/IDE/开机自启
::      ai-monitor.exe --heal              ← 扫除任何孤儿 AutoConfigURL / HTTP_PROXY

:: 2) 想自检本机是不是真的"干净"了，可以用：
reg query "HKCU\Software\Microsoft\Windows\CurrentVersion\Internet Settings" /v AutoConfigURL
reg query "HKCU\Environment" /v HTTP_PROXY
reg query "HKCU\Environment" /v HTTPS_PROXY
:: 三条都应该返回「找不到」或为空。
```

诊断接口：当 `ai-monitor.exe` 在跑时，访问 `http://127.0.0.1:18090/status` 会返回 JSON，其中 `network_takeover` 字段会清晰显示当前接管模式与所有写入的系统设置，便于排障：

```json
{
  "network_takeover": {
    "mode": "observe",              // observe / session / persistent
    "auto_config_url": "",
    "pac_is_self": false,
    "system_proxy": "",
    "system_proxy_is_self": false,
    "user_http_proxy": "",
    "user_https_proxy": "",
    "ca_path": "C:/Users/x/AppData/Roaming/ai-monitor/ca.crt"
  }
}
```

如何**主动**接管：

- **默认（双击 ai-monitor.exe）就是会话 PAC 接管**——AI 域名走 MITM，其它流量直连，关闭程序自动还原；
- **临时**显式启用：`ai-monitor.exe --with-session-pac`（即使 `config.json` 关了 session pac 也会强开本次）；
- **永久接管**（开机自启 + 写 PAC/环境变量/IDE）：`ai-monitor.exe --global-install`；
- **仅当前进程**：`ai-monitor.exe --launch <你的程序>` 或 `--launch-preset vscode/cursor/powershell/cmd`。

### 怎么验证 token 真的被记下来了？

启动 ai-monitor → 在 Cursor / Copilot / Codex 里发一条 AI 请求 → 跑一次：

```powershell
Invoke-RestMethod "http://127.0.0.1:18090/status" | ConvertTo-Json -Depth 5
```

看 `stats.total_reported` 是否 `> 0`、`network_takeover.mode` 是否 `"session"`、`auto_config_url` 是否含 `proxy.pac`。如果接管模式是 `"observe"`，说明本次没接管 → 看 `config.json` 里的 `auto_install_session_pac` 是否被设成了 `false`。

## 十二、隐私与安全说明

- MITM 会解密 **列入监控名单的 HTTPS 站点**；请仅在 **公司授权的设备与网络策略** 下使用。
- `config.json` 含上报地址与个人信息，**勿提交到公开仓库**；分发时使用示例配置并替换为内网地址。

---

## 十三、与仓库其他部分的关系

- 仓库中另有 **backend / frontend**（大屏与 API），客户端只负责 **采集与上报**。
- 服务端部署、防火墙与网关策略由运维在服务器侧配置，不在本文展开。
